# Kite 格式化规则（kitec fmt）

目标：同一段程序只有一种排版（只有少数几处刻意留给作者选择）；幂等；绝不改变程序含义。

## 1. 基础

- 行宽 100 列。中日韩等全角字符算 2 列；行尾 `//` 注释不计入行宽。
- 缩进 2 个空格，不用 Tab；行尾不留空白；文件以单个换行结尾。
- 放不下又没有可断点的行（长字符串、长标识符）保持原样。

## 2. token 之间的空白

- 二元运算符、赋值、`=>`、`->` 两侧各一个空格；`,` `;` `:` 后面一个空格、前面不留。
- `..` `..=` `::` `.` 两侧都不留；一元 `-` `!` `~` 紧贴操作数。
- `(` `[` 内侧不留空格；`{ … }` 内侧各一个空格；集合字面量 `Set{1, 2}` 的 `{` 紧贴 `Set`、内侧不留。
- 泛型 `List<T>`、`fn f<T: Ord>(…)` 的尖括号两侧不留空格，和比较运算 `a < b` 自动区分；`List<List<Int>>` 收紧成 `>>`。
- 关键字后面跟 `(` `[` 时留空格：`if (a, b)`、`for (k, v) in m`。

## 3. 空行

- 连续空行压成一个；`{` 之后、`}` 之前、文件开头和结尾不留空行。
- 括号列表里的空行（最多一个）保留，此时列表总是展开。

## 4. 语句与块

- 语句之间的换行有语义，全部保留；`;` 保留原样。
- 原来写成多行的块保持多行。
- 单行块 `{ x }` 放得下就保持单行，放不下就展开。if / else 链里的单行块同进同退：整条语句放不下时先把块全部展开，然后才考虑断条件。
- 空块写作 `{}`；`} else` 总在同一行。
- `{` 后面同一行的注释留在 `{` 后面。

## 5. 括号列表

适用于 `(…)` `[…]` 和用逗号分隔的 `{…}`，例如调用参数、形参、列表/元组/记录字面量、模式、记录类型、match 分支、use 列表。

按下面的顺序尝试，用第一个放得下的：

1. **单行**：去掉尾逗号。
2. **拥抱**：最后一项是闭包或块、`{…}`/`[…]` 字面量，或者本身就是多行的东西时，前面几项留在同一行，只展开最后一项：
   ```
   map(xs, (x) => {
     …
   })
   ```
3. **展开**：每项占一行，缩进一级，加尾逗号，闭括号独占一行。
   `[…]` 里如果每一项都是不超过 10 列的单个 token（数字、短字符串、标识符），改为按行填满：
   ```
   const OPS: List<Str> = [
     "=", "==", "!=", "<=", ">=", "+", "-", "*", "/", "%", "&&", "||", "|>", "=>", "->", "+=", "-=",
     "*=", "/=", "%=",
   ]
   ```

由作者决定的情况：

- **魔法尾逗号**：`(…)` `[…]` 原来写成多行、最后一项后面有逗号时保持展开；没有尾逗号就按上面的顺序重新排。
- `{…}` 列表（记录、match 分支等）原来写成多行就保持多行。
- 列表里有注释或空行时总是展开；注释原样保留（逗号后同一行的注释跟着上一项）。

尾逗号细节：单元素的括号表达式 `(x)` 不加尾逗号；单元素元组 `(x,)` 的逗号始终保留；索引 `a[i]`、以 `..` 开头的最后一项（`..base`、`..rest`）不加尾逗号。

## 6. 语句内的断行

一条语句放不下时，按从外到内的顺序断开，外层断开后还放不下才断内层：

1. **赋值右边**（`=` `+=` 等，以及 match 分支的 `=>`）：右边从第一个可断点开始的那一截在这一行放不下（例如一长串 `+` 拼接）时，在运算符后面换行，右边缩进一级。
2. **逻辑运算和管道**：只在优先级最低的那一类运算符前断开（`|>` 低于 `||`，`||` 低于 `&&`），后续行缩进一级，要么全断要么都不断；每一段内部再按同样规则递归。
   ```
   if o <= 0x115f
     || o >= 0x2e80 && o <= 0xa4cf
     || o >= 0xac00 && o <= 0xd7a3 {
   ```
3. **方法链**：至少有两次 `.方法(…)` 调用时，可以在每个 `.` 前断开，后续行缩进一级；链中间（不是最后一次调用）出现多行闭包时总是断开。
4. **括号列表**（第 5 节）。

作者在 `.` `&&` `||` `|>` `else` `?` 前面换的行，以及在 `=` `&&` `||` `|>` `.` 后面换的行，都由格式化器重新决定。在其他二元运算符（`+` `==` 等）后面换的行保留，续行缩进一级。

## 7. match

- 分支的 `=>` 不再对齐（改一行会牵动整组，diff 很乱）。
- 多行 match 每个分支占一行，用逗号分隔的分支末尾都加逗号。

## 8. 注释

- 全部保留；行尾注释和代码之间的空白保持原样（至少一个空格）。
- 一条语句中间夹着注释时，这条语句里的换行全部保持原样。

## 9. 安全网

- 输出要和输入用正式词法分析器比对：token 序列和语句分隔（NEWLINE）必须一致，只允许闭括号前的尾逗号不同。
- 输入能被解析时，输出也必须能被解析。
- 任一项不满足就拒绝输出并报错（不应发生）。
- 幂等：`fmt(fmt(x)) == fmt(x)`。
